# 个人知识库 RAG Agent —— 项目计划书

> 本文件是交给 Qoder 的开发计划书。请按「开发步骤」逐阶段执行，每完成一步按该步的验证方式确认后再进入下一步。

## 1. 项目概述

把用户的课程笔记、大创项目文档、PDF 资料等散落文件，变成一个可问答的智能知识库：用户提问，系统只依据库内资料生成回答，并标注引用来源，不编造。

- 交付形态：Python 命令行程序（CLI），本地运行
- 数据来源：用户电脑 `E:\个人知识库 RAG Agent\输出资料存放处`（含子文件夹）
- 支持的文档格式：`.pdf`、`.docx`、`.txt`（txt 需为 UTF-8 编码）

## 2. 范围（本版只做 MVP，不做 Web 界面）

| 做 | 不做（留到扩展阶段） |
|---|---|
| 文档导入：解析 → 分块 → 向量化 → 入库 | Web/图形界面 |
| 命令行问答：检索 → LLM 生成带引用回答 | 多会话记忆、文档去重合并 |
| 增量入库：重复运行不产生重复块 | 扫描版 PDF 的 OCR |
| 配置全部集中在 `.env` | 在线向量 API（本地向量模型免费离线） |

## 3. 功能需求

### 3.1 配置（`.env`，用 python-dotenv 读取）
- `LLM_BASE_URL`：在线 LLM 接口地址，默认 `https://api.deepseek.com`
- `LLM_API_KEY`：用户自己的 key，未填或为占位符「把你的key粘贴到这里」时，query 启动给友好提示并退出
- `LLM_MODEL`：默认 `deepseek-chat`
- `DATA_PATH`：文档文件夹路径（Windows 反斜杠写法，示例 `E:\个人知识库 RAG Agent\输出资料存放处`）
- `DB_PATH`：向量库目录，默认 `db`
- `TOP_K`：每次召回的文本块数量，默认 5

同时支持豆包/火山方舟：`LLM_BASE_URL=https://ark.cn-beijing.volces.com/api/v3`，`LLM_MODEL` 填推理接入点 ID。只改 `.env` 即可切换，代码不写死任何一家。

### 3.2 文档导入（`ingest.py`）
1. 递归扫描 `DATA_PATH` 下所有支持格式的文件
2. 按格式解析为纯文本：
   - PDF：pymupdf 逐页提取，每页前加 `[第N页]` 标注（兼容导入：`import pymupdf as fitz`，失败回退 `import fitz`）
   - DOCX：python-docx 提取段落文本
   - TXT：UTF-8 读取，乱码字符丢弃
3. 分块策略（已验证为最优参数）：
   - 按空行分隔段落，把连续段落累积到接近 300 字符成块，保证每块主题连贯
   - 单个段落超过 300 字符（如 PDF 整页无换行）时，按固定长度 300 切分、相邻块重叠 30 字符
4. 向量化：本地模型 `BAAI/bge-small-zh-v1.5`（sentence-transformers），`normalize_embeddings=True`
5. 写入 chromadb：
   - `PersistentClient(path=DB_PATH)`，collection 名 `knowledge_base`，距离 `cosine`
   - 每条记录的 id = `文件名-块序号-内容哈希前10位`（重复运行同内容不产生重复块）
   - metadata 记录来源文件名 `source`
6. 入库前打印每个文件的块数，入库后打印库内总条数

### 3.3 问答（`query.py`）
1. 检索：问题向量化时加 bge 官方前缀「为这个句子生成表示以用于检索相关文章：」，召回 `TOP_K` 条
2. 组装：system 提示「只依据资料回答；资料没有的内容明确说『资料里没有相关信息』，不要编造；句末用 [来源N] 标注引用」；上下文按 `[来源N] 文件名\n正文` 格式编号
3. 生成：openai SDK（`OpenAI(base_url=..., api_key=...)`），temperature 0.3
4. 交互：命令行循环，输入 `exit` / `quit` / `退出` 结束
5. 输出回答后，列出引用资料及相似度

### 3.4 代码规范（硬性要求）
- 双引号、4 空格缩进、变量名见名知意、一行一件事
- 函数带中文 docstring，注释用中文
- 不引入 Web 框架、不写多余依赖

## 8. 已知注意事项（避免踩坑）

1. pymupdf 新版包名已改为 `pymupdf`，必须兼容新旧两种导入写法
2. bge 检索必须给问题加前缀「为这个句子生成表示以用于检索相关文章：」，否则召回明显变差
3. 分块上限 300 字符是调优后的值，不要随意改大（块内混主题会拉低召回）
4. txt 必须 UTF-8 编码，否则乱码（解析时 `errors="ignore"` 兜底）
5. `DATA_PATH` 是用户 Windows 路径，代码不得硬编码，只能从 `.env` 读
6. 首次运行下载向量模型约 100MB，属正常现象，不要中断
